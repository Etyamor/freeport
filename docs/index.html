“Port 3000 is already in use.” By what, exactly?

lsof -i :3000 tells you the port is held by OrbStack. That is true and useless — you still don't know which of your eight containers it is, or how to stop it. FreePort resolves the actual owner.

What it does

Built for the Docker + DDEV + Node mix, where the process name alone never answers the question.

◧

Container-aware

Ports held by the Docker proxy are matched back to the real container through the Docker socket. Works with Docker Desktop, OrbStack, Colima and Rancher Desktop.

▦

DDEV-aware

Containers group by their com.ddev.site-name label. Freeing one port stops the whole project — web and db — instead of leaving half a site running.

⌘

Project paths, not just “node”

Node and Bun processes show their working directory, so three node rows are actually distinguishable at a glance.

✕

Frees correctly, not bluntly

A process gets SIGTERM, 1.5 seconds to exit, then SIGKILL. A container is stopped via the Docker API — killing the proxy would not release the port.

⚿

Safe by default

Only processes you own can be signalled. System daemons are refused outright, and shared infrastructure like ddev-router asks for confirmation first.

◇

Native and tiny

Swift and SwiftUI, under 1 MB, no Electron, no background CPU burn. Idles at a 20-second poll and speeds up only while the popover is open.

Install

Two options. Building from source takes a few seconds and skips the Gatekeeper step.

  1. Download the latest release, unzip it, and drag FreePort.app to your Applications folder.
  2. Clear the quarantine flag macOS puts on downloaded apps: 
    xattr -dr com.apple.quarantine /Applications/FreePort.app
  3. Launch it and look for the plug icon in your menu bar.

Or build it yourself:

git clone https://github.com/Etyamor/freeport.git
cd freeport
./build.sh --install

FreePort is ad-hoc signed rather than notarized, because notarization requires a paid Apple Developer account and this is free software. Building from source avoids the quarantine flag entirely.

There's a CLI too

The same binary runs headless, so you can stay in the terminal when you're already there.

# every listening port, with its real owner
FreePort --list

# release whatever is holding :3000
FreePort --free 3000

# worth aliasing
alias ports='/Applications/FreePort.app/Contents/MacOS/FreePort --list'
alias freeport='/Applications/FreePort.app/Contents/MacOS/FreePort --free'

Frequently asked questions

How do I find what is using a port on macOS?

From the terminal, lsof -nP -iTCP:3000 -sTCP:LISTEN shows the process holding port 3000. FreePort shows every listening port at once in your menu bar, and — unlike lsof — names the Docker or DDEV container behind the port instead of the shared proxy process.

How do I kill a process running on a port on macOS?

In the terminal: kill $(lsof -ti :3000). In FreePort, click the ✕ beside the port. FreePort sends SIGTERM first and only escalates to SIGKILL if the process ignores it, so your dev server gets a chance to shut down cleanly.

Why does lsof show “OrbStack” or “com.docker.backend” instead of my container?

On macOS, Docker runs inside a virtual machine and every published port is forwarded by one shared proxy process — so all your containers look identical from the outside. FreePort queries the Docker socket and matches each published port back to the container that actually owns it.

Can it free a port used by a Docker or DDEV container?

Yes, and it does it the right way. Killing the proxy process would not release the port, so FreePort stops the container through the Docker API instead. For DDEV it stops every container in that project, so you don't end up with a running database and no web server.

Is FreePort free?

Yes — free and open source under the MIT license. No account, no telemetry, and no network access beyond your own local Docker socket.

macOS says the app is damaged or can't be opened. What now?

That's Gatekeeper's quarantine flag on a non-notarized download. Run xattr -dr com.apple.quarantine /Applications/FreePort.app once, or build from source with ./build.sh --install, which never sets the flag.

Can it free ports owned by root or another user?

No. Those ports are listed so you can see them, but releasing one would require sudo — which a menu bar app has no business holding. System daemons are protected outright.
